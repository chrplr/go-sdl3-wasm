# go-sdl3

Pure-Go SDL3 bindings (no CGo). Native platforms link the SDL3 dynamic library
at runtime via `ebitengine/purego` (`*_functions.gen_impl.go`, build tag `!js`).
The browser/WebAssembly target instead calls an Emscripten-compiled SDL3 module
through `syscall/js` (`*_functions_js.go`, build tag `js`).

## WebAssembly / browser support

This section documents work done to get go-sdl3 programs rendering in the
browser (Go compiled to `GOOS=js/GOARCH=wasm` against an Emscripten-built SDL3).

### How the browser path is meant to work

- `cmd/wasmsdl` builds the user program with `GOOS=js GOARCH=wasm` and bundles
  it with `index.html`, `wasm_exec.js`, and the prebuilt Emscripten SDL3 module
  `cmd/wasmsdl/assets/{sdl.js,sdl.wasm}` (which includes SDL3, SDL3_image,
  SDL3_ttf). Run with `go run ./cmd/wasmsdl serve ./path/to/app`.
- The program's frame loop must go through `sdl.RunLoop`; on js this drives the
  frame with `emscripten_set_main_loop` (a hand-written `for { PollEvent; Delay }`
  loop freezes the browser tab).
- The js bindings are generated by `cmd/jsgen`, which emits
  `panic("not implemented on js")` as the first line of every function. A
  function only works once that panic is removed and its argument/return
  marshaling is verified. Most functions are still stubbed.

### Root-cause bugs found and fixed

These were blocking *all* browser rendering (helloworld included), independent of
function coverage:

1. **Canvas had no size → 0×0 window → nothing rendered.** SDL3's Emscripten
   backend uses the canvas CSS layout size (`getBoundingClientRect`) as the
   window size. The old `cmd/wasmsdl/assets/index.html` gave the canvas no CSS
   size (flex-centering collapsed it to 0). Fixes:
   - `sizeCanvas(w, h)` helper in `sdl/glue_js.go`, called before the SDL call in
     `iCreateWindow` and `iCreateWindowAndRenderer`, sets the canvas CSS pixel
     size to the requested window size so SDL reads it back correctly.
   - Rewrote `cmd/wasmsdl/assets/index.html` so the canvas no longer collapses.
2. **`sdl.RunLoop` passed fps `-1`** to `emscripten_set_main_loop`; changed to
   `0` so emscripten uses `requestAnimationFrame` (`sdl/init_js.go`).
3. **`cmd/wasmsdl` couldn't find `wasm_exec.js`** under `go run` (it only checked
   the `GOROOT` env var, unset there) and silently fell back to a network fetch.
   Added a `goRoot()` fallback to `go env GOROOT` (`cmd/wasmsdl/main.go`).

### Function coverage added

Un-stubbed/fixed the 2D-render, image, and text paths in `*_functions_js.go`:

- **Render** (`sdl/`): `CreateWindow`, `CreateRenderer`, `RenderPoint`,
  `SetWindowSize`, texture modulation (`SetTextureBlendMode/ScaleMode/ColorMod/
  AlphaMod`), out-param getters (`GetTextureSize`, `GetRenderOutputSize`,
  `GetRenderScale`), `SetRenderTarget`. Also fixed latent `int32(float)`
  truncation bugs (e.g. `SetRenderScale`).
- **Audio** (core SDL, `sdl/`): `OpenAudioDeviceStream` (was commented out),
  `ResumeAudioStreamDevice`, `PutAudioStreamData`, `GetAudioStreamQueued`,
  `DestroyAudioStream`. The audio symbols are present in the prebuilt module (no
  rebuild needed — unlike mixer). `PutAudioStreamData` copies the PCM into the
  wasm heap; `OpenAudioDeviceStream` copies the `AudioSpec` and treats
  `userdata`/`callback` as `i32`. Browser autoplay policy means sound only
  starts after a user gesture (click/keypress).
- **Text** (`ttf/`): `Init` was already working; added `Quit`, `CloseFont`,
  fixed `OpenFontIO` (was truncating the float `ptsize`), and the full
  `RenderText_*` family — `Solid`, `Shaded`, `Blended`, `LCD` and their
  `_Wrapped` variants (`Shaded`/`LCD` were previously commented out). All pass
  `SDL_Color` by pointer (see marshaling notes) and were truncating `size_t`
  length via `NewBigInt`; now use `int32`.

### Codegen improvement

`cmd/jsgen/main.go` now generates correct bodies for floats (pass through instead
of `int32(x)`) and float return values (`.Float()`), so future un-stubbing
doesn't reintroduce the truncation bug. The leading `panic` is kept as a
"needs verification" marker.

### Marshaling idioms (when un-stubbing more functions)

Helpers live in `internal/` (js-tagged). The js function body usually needs:

- opaque handle in (`*Renderer`, `*Texture`, `*Window`) → `internal.GetJSPointer`
- value struct passed by *pointer* in the Go signature (`*FRect`, `*Color`) →
  `internal.CloneObjectToJSStack`
- small struct passed *by value* in the C API (e.g. `SDL_Color` taken as a
  `uint32` in the binding) → the wasm ABI lowers it to a pointer arg, so
  `internal.StackAlloc(4)` + `internal.SetValue(ptr, js.ValueOf(int32(packed)), "i32")`
  and pass the pointer (model: `ttf` `iRenderText_Blended`). Passing the packed
  value directly causes a "memory access out of bounds" crash.
- scalar out-param → `internal.StackAlloc(4)` then
  `internal.GetValue(ptr, "i32"|"float")` read-back (model: `iGetWindowSize`)
- handle return → null-check `ret.Int()==0` then `internal.NewObject[T](ret)`
- 64-bit flags → `internal.NewBigInt(uint64(x))`
- floats → pass through unchanged (do NOT cast to int32)
- byte buffers across the module boundary → `internal.CloneByteSliceToJSHeap`
  (Go's wasm memory and the Emscripten heap are separate)

### Assets in the browser

There is no real filesystem, so path-based loaders won't work without Emscripten
FS preloading. The portable approach (works native and web) is `go:embed` the
bytes → `sdl.IOFromConstMem(bytes)` → `img.LoadTextureIO` / `ttf.OpenFontIO`.
`IOFromConstMem` already copies the bytes into the Emscripten heap.

### Verification examples

- `examples/wasmcheck` — 2D render path (window/renderer, points, primitives,
  render-target texture with modulation, out-param read-back).
- `examples/imgttf` — SDL3_image (decodes a runtime-generated PNG) and SDL3_ttf
  (renders embedded-font text), both via in-memory IOStreams.

Verify in a browser (`go run ./cmd/wasmsdl serve ./examples/<x>`); each remaining
stub panics in the JS console with its symbol name, which tells you what to
un-stub next.

### Not yet working: audio / mixer

The prebuilt `cmd/wasmsdl/assets/sdl.js` does **not** export `_Mix_*` symbols
(`EXPORT_ALL` drops unreferenced members of the static `libSDL3_mixer.a`). Before
any Go-side mixer work matters, rebuild the Emscripten module via
`.docker/emscripten-build/Dockerfile`, force-linking the mixer archive
(`-Wl,--whole-archive`), and replace `sdl.js`/`sdl.wasm`. Gate: `grep -c
_Mix_OpenAudio cmd/wasmsdl/assets/sdl.js` must be > 0.

## Building / testing

- Native build: `go build ./...`
- Browser build check: `GOOS=js GOARCH=wasm go build ./...`
- Run an example natively: `go run ./examples/<name>`
- Run an example in the browser: `go run ./cmd/wasmsdl serve ./examples/<name>`
